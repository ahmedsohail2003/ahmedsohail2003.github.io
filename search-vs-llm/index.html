Multi-Agent Adversarial AI

Search vs LLMBenchmark

A four-agent benchmark pitting classic game-tree search against a Gemini-powered player, where every LLM move is validated before it touches the board.

  • Python
  • Gemini API
  • Minimax
  • Alpha-Beta pruning

View the repository

The problem

Ask a language model for a move and the reply may not parse, may point off the board, or may break the rules. Benchmarking it against classic search means checking every move before it is played, and measuring every agent in numbers that can be compared.

What I built

My part

I owned the LLM agent

Prompt construction, response validation, corrective re-prompting and evaluation for the Gemini-powered player, in a team of four.

Validation

Nothing unchecked reaches the board

Every model move must pass parse, bounds and legality checks. A failure triggers a corrective re-prompt; repeated failure falls back to a deterministic move.

Instrumentation

Counters on every agent

Search-node counters across all four agents, plus LLM metrics for real API requests, first-try validity and retries.

Testing

A regression test caught my own bug

It exposed under-pruning in the benchmark. The fix raised measured node reduction from 94.4% to 96.7% versus plain minimax. The Python test suite runs on GitHub Actions CI.
